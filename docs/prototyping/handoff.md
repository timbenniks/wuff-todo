# Send a feature Tim can build

When you are happy with the prototype, ask the agent to prepare this brief. A good title names the behavior or user benefit. Put the essential requirements in Wuff notes; link supplementary research and larger documents.

## Feature brief

### Problem and intended users

What is awkward today? Who benefits, and what should become easier?

### Agreed scope

What is included? What stays out of this version? Which parts are existing Wuff behavior and which are new proposals?

### Behavior and states

Describe the main flow, entry points, inputs, outputs and where the user returns. Include relevant empty/loading/pending/saved/error/denied/conflict states and what happens on cancellation or deletion.

### Permissions and personal/shared behavior

Who can see or change this? Is the result personal or shared? Explain any proposed permission change. Include how archived lists and removed access affect the experience when relevant.

### Design reference

Link the reviewed prototype version and its source/export. Check that Tim can open the shared URL in your workspace. Attach annotated phone and desktop screenshots, noting the important interactions. Record the design-kit source commit/hash manifest. Use existing component names and identify new components or token changes as proposals.

### Acceptance criteria

Use observable outcomes: “An editor can save their own daily-list preference without changing the owner’s preference,” rather than “Settings work well.” Include the relevant phone, keyboard/focus and failure-recovery outcomes.

### Open questions and review evidence

List unresolved choices, assumptions, mocked behavior and what was actually checked. Do not turn an unanswered question into a requirement. Keep any later scope change explicit so the prototype and specification remain aligned.

## Save it in Wuff

Ask the agent to create or update the intended task in your shared Work list. It should check for an existing task, preserve prior content, attach only images you approved and verify the result. A task link, prototype link and longer notes link have different jobs: include each with a clear label.

If the agent has no connected Wuff tools or the list is ambiguous, it should provide a ready-to-paste title and notes or ask which list to use. The skill does not grant access. Saving a design brief does not authorize starting a paid coding agent or changing the production app.

Use the existing Work states: Todo for work ready to pick up, In progress while building, In review for feedback, Blocked for an unresolved dependency and Done when agreed acceptance criteria are met. Draft exploration can stay in the design conversation until you choose to save it.
