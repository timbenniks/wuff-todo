Existing live task changes and polling refresh these summaries; sync-only state changes can wait for the normal polling interval.
2. **Optional native GitHub consent.** Basic native sign-in still requests only read/task/list permissions. “Enable GitHub sync” starts a new browser PKCE consent requesting `github:manage`. `/oauth/native` advertises it as optional; the bearer session reports actual granted scopes. Old grants and token refresh cannot acquire it implicitly. An interactive upgrade advances the client account generation so a late basic-grant refresh cannot overwrite new credentials; the superseded local grant is revoked best-effort. Browser cancellation leaves existing credentials alone. A successful reconnect clears prior-account list/draft state before loading the authorized account.

GitHub links have the same target minimum. Direct More/Delete/drag controls remain on the main row. More shows the full title and an explicit Open task details link. ## First mobile release: agreed requirements

The user explicitly selected **native task notes and private images** as release requirements on October 18. These are requirements for the next native implementation slice, not a claim that the current native source already implements them.

Required before a usable first iPhone/Android release:

- Invited-account browser sign-in, secure session restoration, refresh/sign-out and separate native token audience.
- Private/shared lists, owner controls and existing-account invitation lifecycle; dates, independent subtasks and manual order.
- Work status/priority and visible issue linkage/sync state, with optional explicit GitHub consent for synchronized writes.
- Read/edit/save task notes natively while preserving canonical Markdown and unsupported content. Keep drafts through recoverable failures and expose stale saves rather than overwriting another editor.
- View, select/upload and remove private task images from native notes, with task ownership/current membership checks, bounded uploads and no public Blob delivery or provider export. Validate the actual device photo picker and revoked-access behavior.
- Common list palettes, DM Sans, accessible controls, full-title access, keyboard-safe editing and tested foreground/network-error recovery.

The existing native notes/images website fallback is insufficient for this agreed release gate. First implement their native transport/UI on the existing domain services; then validate installed simulator/device auth, photo access, keyboard, VoiceOver/TalkBack and secure storage. Current code exports are packaging evidence only.

Online-only remains confirmed: no persistent task cache, offline write queue, notifications, scheduling, widgets or background sync. Agent execution remains deferred. Assignee/reference editing, repository setup, section administration, sidebar/personal-view administration and distribution polish can follow unless the user selects them sooner; existing values must remain intact when omitted from edits.
