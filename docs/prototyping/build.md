# Build a real feature

Use this path when Tim has supplied a contributor workspace connected to the real
Wuff repository. You describe the result and try it; your agent manages code, Git,
verification and the PR. Tim approves technical scope and reviews the result.

For exploration without a repository, use [Make a prototype](/docs/prototyping).
The prototype kit uses mocks and cannot deliver a connected feature on its own.

## Give your agent this starter

> I want to implement a Wuff feature in this repository. Read AGENTS.md and
> docs/contributor-workflow.md, then use the wuff-contributor skill if available.
> Help me define behavior and acceptance criteria, create a codex/ branch and draft
> PR, and request Tim's scope approval before implementation. Handle Git and
> verification for me. Preserve Wuff's components, permissions and recovery
> behavior. Show me a safe preview once the backend is confirmed isolated. Keep
> evidence and remaining gaps in the PR. Do not merge or release. My idea is:

## What happens next

Describe → agree the brief → Tim approves scope → build → try the preview → refine
→ checks and evidence → Tim reviews → Tim merges/releases.

The full contributor workflow follows and is available as a plain-text download.
