# Build a feature

Work in the actual Wuff repository, using its components, contracts and authorized
services. You choose the behavior; your agent manages implementation and delivery.

## Give your agent this starter

> Use the wuff-contributor skill. Read AGENTS.md and docs/contributor-workflow.md in
> this repository, plus the product, design, component and accessibility guide.
> Help me define the problem, behavior and acceptance criteria. Create a codex/
> branch and draft PR, and get Tim's technical scope approval before implementation.
> Reuse Wuff's actual components and tokens, show the main interaction early, and
> iterate with me. Preserve permissions, personal/shared boundaries and save recovery.
> Handle Git and verification for me. Use synthetic data and only a confirmed
> isolated preview backend. Keep decisions, current-commit evidence and remaining
> gaps in the PR. Do not merge or release. My idea is:

## One workflow, including exploration

Sketching, small local mocks and visual experiments are useful steps inside the
feature's draft PR. They do not become a separate app, a replacement component
system or evidence of real persistence. Clearly label simulations and connect the
actual behavior through existing services only within approved scope.

The full contributor workflow follows and is also available as a download above.
